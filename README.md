# AirTouch — управление смартфоном жестами в воздухе

Управление телефоном без касаний, как обычным, только в воздухе (фронтальная камера + MediaPipe, всё на устройстве).

Жесты построены на **движении**, а не на форме руки, — поэтому не путаются:

| Движение | Действие |
|---|---|
| мах любой формой руки | свайп ←→↑↓ (резкий мах «за край кадра» тоже считается) |
| тык — рука к экрану и обратно | домой |
| тык и задержать руку у экрана | недавние приложения |
| ✌️ «V» неподвижно 0,45 с | назад |
| режим курсора (вкл. в настройках): ☝️ / 🤏 | курсор; щипок — тап, вести — прокрутка, держать — долгое нажатие |

**Воздушная клавиатура** (RU/EN): открыли поле ввода — поверх системной клавиатуры появляется своя.
🤏 щипок и росчерк через буквы — слово целиком (декодер в стиле SHARK²: форма росчерка + частотность слова),
быстрый щипок — буква, сверху 3 варианта, ⌫ после росчерка стирает слово, заглавные и пробелы — сами, ✌️ — закрыть.
На синтетических «неряшливых» росчерках: верное слово первым в ~88% случаев, в тройке — ~95%.
Текст вставляется через службу спец. возможностей (ACTION_SET_TEXT) в поле с фокусом.

Тык отличается от поворота кисти: при приближении к камере растут и длина, и ширина ладони.
Позы распознаёт обученная модель MediaPipe Gesture Recognizer, а не самодельные правила.
В приложении видно реальные кадры/с и задержку распознавания.

Удержания показывают кольцо прогресса. Работает, пока горит экран; экран погас — пауза, включился — продолжает сам.

## Быстрый старт

1. Откройте папку `AirTouch` в Android Studio (Ladybug или новее), дождитесь синхронизации Gradle.
2. Первая сборка сама скачает модель `gesture_recognizer.task` (~8 МБ) в `app/src/main/assets/`
   (Gradle-задача `downloadHandModel`). Без интернета положите файл туда вручную:
   `https://storage.googleapis.com/mediapipe-models/gesture_recognizer/gesture_recognizer/float16/1/gesture_recognizer.task`
3. Запустите на реальном телефоне (эмулятор с камерой работает плохо).
4. В приложении пройдите 3 шага: камера → уведомления → служба специальных возможностей.
5. Нажмите «Включить» или плавающую кнопку ✋ — и махните ладонью в сторону камеры.

Юнит-тесты логики жестов (без устройства): `./gradlew :app:testDebugUnitTest`

## Как это работает

```
CameraX ImageAnalysis (640×480, keep-latest)
   │  поворот + зеркало для фронталки
   ▼
HandTracker (MediaPipe, on-device)  ──►  HandFrame (21 точка)
   ▼
GestureDetector  ──►  AirGesture.SwipeLeft/Right/Up/Down
   ▼
AirInputService.dispatchGesture()   ──►  свайп в текущем приложении
   │
   └─► AirTouchState ──► OverlayController (кнопка, точка-трекер)
```

### Алгоритм свайпа (`GestureDetector`)

1. Берём **центр ладони** (запястье + основания пальцев): он стабильнее кончиков.
2. Сглаживаем EMA и гасим дрожание **мёртвой зоной**: микросдвиги «прилипают» к предыдущей точке.
3. Храним точки за последние 450 мс. Свайп засчитывается, если от *какого-либо* начала в окне:
   - смещение ≥ `0.25 / чувствительность` короткой стороны кадра;
   - основная ось доминирует (|dx| ≥ 1.7·|dy|), поэтому диагональ не срабатывает;
   - средняя скорость ≥ 0.8 кадра/с, поэтому медленный дрейф не срабатывает.
4. Свайп засчитывается **ладонью или пальцем**; кулак игнорируется (он зарезервирован под drag). Если рука пропала из кадра меньше чем на 0,3 с (смаз при быстром махе), детектор не сбрасывается.
5. **Подавление обратного хода:** после свайпа детектор ждёт, пока рука замрёт хотя бы на 120 мс
   (или уйдёт из кадра). Без этого возврат руки давал бы ложный свайп в обратную сторону.
   Это покрыто тестом, в том числе для «живого» движения с торможением.

Все пороги собраны в `SwipeConfig`, чувствительность и мёртвая зона выводятся в настройки.

### Энергосбережение

| Условие | Что происходит |
|---|---|
| Руки нет 3 с | экономичный режим: обрабатывается каждый 4-й кадр (~7 FPS), точка скрыта |
| Экран погас | камера на паузе; экран включился — продолжает сама |
| Яркость кадра < 45/255 | плашка «Мало света» поверх экрана и в приложении |

Авто-сон по таймеру убран по просьбе пользователя: будить кнопкой каждый раз неудобно.
Цена — расход батареи, пока горит экран. Значения — в `core/AirTouchState.kt → Timeouts`.

## Чем реализация отличается от промпта и почему

- **Разрешение «Поверх других приложений» не нужно.** У AccessibilityService есть свой тип окна
  `TYPE_ACCESSIBILITY_OVERLAY`, поэтому в мастере на один шаг меньше.
- **Камера живёт в foreground service с типом `camera`**, а не в самой службе специальных
  возможностей. Так Android 11+ разрешает держать камеру, пока открыто другое приложение.
- **`ToggleActivity`.** Камеру в FGS можно включить только с переднего плана, поэтому плавающая
  кнопка на 0,3 с открывает прозрачную activity. Пользователь этого не видит.

## Что нужно знать до публикации

- **Google Play строго проверяет AccessibilityService.** Нужна декларация в Play Console и
  обоснование. Честный и подходящий сценарий: управление телефоном без касаний для людей
  с нарушениями моторики. Служба настроена минимально: `canRetrieveWindowContent=false`.
- **Android 13+ при установке APK не из магазина** блокирует включение службы, пока пользователь
  не нажмёт «Разрешить ограниченные настройки». Подсказка есть в мастере.
- **Агрессивные оболочки** (MIUI/HyperOS, One UI, ColorOS) могут убивать фоновые сервисы.
  Добавьте в мастер шаг «Отключить оптимизацию батареи».
- Пока работает камера, Android показывает зелёный индикатор. Если камера уже занята другим
  приложением, например видеозвонком, AirTouch покажет ошибку.

## Дорожная карта

| Этап | Жест | Реализация |
|---|---|---|
| ✅ 1 | Свайп ←→↑↓ | готово |
| ✅ 1.5 | Курсор + щипок (тап, drag, долгое нажатие) | готово |
| 2 | «V» → «Назад» | `HandPose.V_SIGN` уже распознаётся → `AirInputService.back()`; удерживать позу ~300 мс |
| 3 | Кулак = drag | `StrokeDescription(willContinue = true)` + `continueStroke()` каждые ~50 мс, пока кулак сжат |
| 4 | Тап | `HandPose.POINTING` + резкое уменьшение `z` кончика указательного; тап в точку трекера |
| 5 | Pinch-zoom | дистанция большой–указательный → жест из двух штрихов `dispatchGesture` |
| 6 | Калибровка | 3-секундный мастер: средний размер ладони → подстройка `baseDistance` под руку |
| 7 | «Только при поднятой руке» | датчик приближения/гироскоп будит камеру вместо постоянной работы |
| 8 | Громкость | `AudioManager.adjustStreamVolume` на отдельный жест |
